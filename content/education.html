01

설계 범위

GSM8K와 AI Hub 수학 관련 데이터의 파일 구조를 살펴보고 문항, 풀이, 성취기준, 출처를 구분했습니다. 같은 의미로 보이는 값도 원본의 제공 단위와 실제 매핑 가능성을 확인한 뒤 관계로 옮겼습니다.

완료 범위는 관계형 설계와 스키마 생성·카탈로그 조회 검증입니다. 실제 데이터 인제스천과 전체 품질 검증은 이 프로젝트의 완료 성과에 포함하지 않습니다.

02

최종 ERD

원본 문항과 반복 가능한 구조, 풀이와 단계, 교육과정 성취기준과 데이터의 출처를 분리했습니다. 아래는 최종 설계의 테이블을 역할별로 정리한 요약 ERD입니다.

테이블의 역할별 분류

출처·적재 실행

  • REFERENCE_SOURCE_TYPE
  • REFERENCE
  • LOAD_BATCH

문항·평가

  • PROBLEM_TEMPLATE
  • PROBLEM_INSTANCE
  • DIFFICULTY_ASSESSMENT

풀이·단계

  • SOLUTION
  • SOLUTION_STEP
  • SOLUTION_STEP_MAP

교육과정 성취기준

  • ACHIEVEMENT_STANDARD
  • TEMPLATE_STANDARD
  • STANDARD_MAP
  • STEP_STANDARD

개념·단계 연결

  • CORE_CONCEPT
  • STEP_CONCEPT

기본 키와 중복 기준

  • 일반 엔터티 → 대리키
  • 교차 테이블 → 복합키
  • 원본 식별자 → UNIQUE
Template1 → NInstance · Template1 → NSolution → Step map

복잡한 교차 관계와 공통 적재 실행 FK는 요약 도해에서 생략했습니다. 설계 검증 기준은 테이블 15개, FK 20개입니다.

핵심 관계

관계이유
Template → Instance같은 구조의 문항과 구체적인 숫자·정답을 가진 원본 문항을 분리
Template → Solution → Step map문항별 풀이와 단계 순서를 표현하고 단계 연결을 별도로 관리
Template ↔ Standard실제 원본이 제공하는 문항 수준의 성취기준 매핑을 반영
Instance → Reference어느 출처의 어느 원본 문항인지 추적하고 중복 기준으로 활용
03

세 가지 설계 판단

1. 출처와 원본 문항의 식별자를 구분

데이터셋의 출처와 그 출처 안의 문항 번호는 다른 층위입니다. UUID만 매번 생성하면 같은 원본의 재유입을 구분할 수 없어, 출처와 원본 식별자를 묶은 유일성 제약을 설계했습니다.

UNIQUE (reference_id, source_data_name)

2. 원본이 주는 수준으로 성취기준을 연결

튜터링 관점에서는 풀이 단계별 성취기준이 유용하지만, 원본 데이터는 문항 수준으로 제공했습니다. 지금 채울 수 있는 문항 매핑과 추후 단계 매핑을 구분하고, 확장용 테이블은 그 상태를 명시했습니다.

3. 난이도를 고정 속성 대신 평가로 표현

한 출처에서 ‘상’인 문항이 다른 평가자에게도 같은 난이도인 것은 아닙니다. 문항의 단일 컬럼으로 고정하지 않고 평가자·방법·시각을 가진 별도 평가 테이블로 분리했습니다.

판단 기준
원본에서 관찰한 사실, 서비스가 요구하는 관계, 아직 데이터가 없는 확장 지점을 구분해 설계했습니다.
04

실행 검증과 한계

DDL을 PostgreSQL에서 실행하고 시스템 카탈로그를 조회해 ERD와 실제 테이블·제약조건이 대응하는지 확인했습니다. 아래 수치는 당시 설계 검증 기록입니다.

검사 항목확인 결과의미
테이블15개설계 엔터티와 생성된 테이블의 대응 확인
PRIMARY KEY15개테이블별 기본 키 확인
FOREIGN KEY20개설계한 참조 관계의 생성 확인
UNIQUE / CHECK3개 / 9개중복 기준과 도메인 제약의 생성 확인
PK 구조교차 5개 복합키 / 일반 10개 단일키설계 원칙의 실제 적용 확인
검증의 범위
스키마 생성과 제약조건의 존재를 확인했습니다. 실제 데이터 적재, 오류 입력의 거부 테스트, 조회 성능 개선은 별도 검증이 필요한 범위로 남겨 두었습니다.

설계 근거는 원본의 식별 기준, 제공되는 성취기준 매핑 단위, 난이도 평가 주체를 기준으로 정리했습니다.
