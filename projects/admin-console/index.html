01

제품과 담당 범위

콘솔은 환자 상태를 확인하고 수면·처방·기기 이력을 살펴보는 협업 제품입니다. 저는 주로 그 화면에 필요한 데이터 구조와 조회·변경 계약을 담당했습니다.

제 기여

업무 의미와 상태 정의, PostgreSQL 모델·View·제한 함수, 업체·운영자 권한 경계, 백엔드·배치 처리와 상대 저장소 계약 검증.

협업 제품

화면 구성과 프런트엔드 구현은 협업 결과입니다. 제품의 화면과 제가 담당한 데이터 모델·조회·변경 계약을 연결해 소개합니다.

화면 자료에 대해
실제 콘솔 프런트엔드를 로컬에서 실행하고 모든 API 응답을 가상 데이터로 대체해 촬영했습니다. 이름·차트·기기번호는 데모 표기이며 운영 서버나 환자 데이터에 연결하지 않았습니다.
02

환자 대시보드

환자 목록에 처방 만료, 사용시간, AHI 관련 지표와 검색·필터를 모았습니다. 숫자를 표시하는 화면 뒤에서는 집계의 날짜 범위, 자료 부족과 실제 0의 구분, 환자 상태를 일관되게 전달해야 합니다.

01 · 집계 범위

같은 범위의 집계

상단 지표와 목록 필터가 같은 환자 범위와 조건을 가리키도록 조회 계약을 맞춥니다.

02 · 누락 데이터

없음과 부족을 구분

수집된 사용 0과 수집되지 않은 날짜를 같은 정상 수치로 해석하지 않도록 합니다.

03 · 이력

날짜가 있는 추이

단순 최신 N건과 연속 날짜 구간의 차이를 고려해 수면 기록을 전달합니다.

03

환자 상세와 이력

환자 상세는 수면 추이와 일별 기록, 처방 이력, 사용 기기를 연결합니다. 처방의 현재·과거·무효 상태를 구분하고, 기기 배정 이력을 현재 환자의 맥락에서 확인할 수 있게 합니다.

처방 상태의 구분

현재 처방을 고를 수 없는 상태와 처방 이력이 아예 없는 상태는 다릅니다. DB의 판정 결과를 화면이 구분할 수 있도록 전달하는 것이 중요했습니다. 읽기 전용 이력과 실제 상태를 변경하는 업무도 별도 계약으로 다룹니다.

04

기기 대장

기기 대장은 개별 기기의 상태, 현재 사용자와 사용 시작일, 배정 이력과 케어 기록을 보여줍니다. 기기 한 대와 환자 한 명의 관계를 현재 행 하나로 덮어쓰지 않고 이력으로 관리하는 구조가 화면을 뒷받침합니다.

05

화면 뒤의 데이터 계약

웹 사용자의 인증과 DB 작업의 권한 판단을 같은 것으로 취급하지 않았습니다. 관리자 콘솔용 DB 역할을 분리하고, 합의된 변경은 운영자와 소속 업체를 확인하는 제한 함수를 통해 처리하도록 했습니다.
